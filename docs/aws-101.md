# AWS 101 — what STReamGT actually runs on

A plain-language tour of the cloud setup, for someone new to AWS. It describes the
architecture as of **September 2026**, after the move off the always-on servers.

For the app's own design see [architecture.md](architecture.md); for the Terraform and
deploy commands see [../infra/README.md](../infra/README.md).

---

## The three things to know first

**1. Everything lives in one account, in one region.** The account is `236726878099` and the
region is `eu-central-1`, which is Frankfurt — the physical place the machines sit. In the AWS
console, the region selector (top right) must say **Frankfurt** or the resources look like they
have vanished. This confuses everyone at first.

**2. A "service" is a rented capability, not a machine.** You don't rent a computer and install
things on it. You rent narrow capabilities — "store these files", "run this code when a request
arrives" — and AWS runs them. Each has its own name and its own price.

**3. You pay for what exists, not what you use.** This is the crucial one for a small project.
A rented server bills every hour it exists, even at 3 a.m. with nobody using it. That is what made
the old setup cost ~$80/month. Today nearly everything here is pay-per-use, and idle cost is
well under $1/month.

## Opening the app

```
Browser
  │
  ▼
CloudFront  (distribution E2ZAMEAEERIVML)          the public front door
  │           https://d2qy3qqpz2ebmu.cloudfront.net
  ├── the web page files ──────────▶  S3 bucket  streamgt-site-236726878099
  └── anything under /api/*  ──────▶  Lambda  streamgt-api
                                         │
                                         ├──▶  Neon      (the database, outside AWS)
                                         ├──▶  S3 bucket streamgt-data-236726878099
                                         └──▶  starts a pipeline task (see below)
```

**CloudFront** is a content delivery network: a worldwide set of caches. Here it does two jobs —
it is the single public address of the app, and it routes each request. Page files come from
S3; anything beginning with `/api/` goes to the Lambda. It also provides the HTTPS certificate.

**S3** (Simple Storage Service) is file storage. Files live in *buckets*, and a bucket name is
globally unique, hence the account number stuck on the end. There are two:

| Bucket | Holds |
|---|---|
| `streamgt-site-236726878099` | the built React app (HTML/JS/CSS) |
| `streamgt-data-236726878099` | FASTQs, results, database backups, pipeline scratch |

**Lambda** runs the FastAPI backend (function `streamgt-api`). Lambda's model: your code sits
dormant, AWS starts a copy when a request arrives, and stops it a few minutes later. You pay per
request and per millisecond of running, so an idle app costs nothing.

Consequences worth knowing:

- **Cold start.** The first request after an idle period waits ~3 s while a copy starts and the
  database wakes. Later requests take ~0.1 s.
- **Nothing is remembered between requests.** No files kept on disk, no in-memory state that
  outlives a request. Anything that must persist goes to the database or S3.
- **Size limit.** One request or response is capped at 6 MB, which is why FASTQ uploads bypass
  the API entirely (below).

**Neon** is the PostgreSQL database — users, projects, samples, genotypes. It is *not* an AWS
service: it is a separate company's free-tier Postgres, in Frankfurt, chosen because it sleeps
when unused and costs nothing at this size. Its connection URL is a secret (see below).

## Running a genotyping job

```
Browser ──upload FASTQ──▶  S3   (direct, not through the API)
   │
   └─"submit job"──▶ Lambda ──run this task──▶  ECS / Fargate task  streamgt-head
                                                   │
                        pulls its software image from ECR
                        reads FASTQs from S3, runs Nextflow + OBITools
                        writes results to S3 and rows to Neon
                        sends the completion email through SES
                                                   │
                                            task shuts down
```

**The upload skips the API.** The browser asks the API for a temporary signed S3 link, then
uploads straight to S3 in parts. A 2 GB FASTQ never passes through the backend — which is what
makes the 6 MB Lambda limit harmless.

**ECS + Fargate** runs containers. A *container image* is your software and all its dependencies
frozen into one package; a *task definition* (`streamgt-head`, currently revision 8) is the recipe
saying which image, how much CPU and memory, and which secrets; a *task* is one running copy.
Fargate means AWS supplies the machine — there is no server of yours to patch.

The pipeline task is deliberately large — **8 CPUs, 32 GB memory, 200 GB scratch disk** — because
OBITools dereplication is heavy. It exists only while a job runs, which is the ~$0.50 per hour
of pipeline time. Between jobs, nothing.

**ECR** (Elastic Container Registry) stores the images:

| Repository / tag | What it is |
|---|---|
| `streamgt-backend:latest` | the pipeline image (backend + Nextflow + OBITools), used by the ECS task |
| `streamgt-backend:api-lambda` | the slim API image (no pipeline tools), used by Lambda |
| `streamgt-backend:head-2026-07-30` | a kept snapshot of the July 2026 pipeline image |
| `streamgt-obitools:latest` | the OBITools base the pipeline image builds on |

**SES** (Simple Email Service) sends the completion emails.

## The supporting cast

| Piece | Names here | What it is for |
|---|---|---|
| **Parameter Store** (part of Systems Manager) | `/streamgt/DATABASE_URL`, `/streamgt/SECRET_KEY`, `/streamgt/SMTP_USER`, `/streamgt/SMTP_PASSWORD` | Encrypted secrets. The Lambda loads them when it starts; ECS injects them into the pipeline task. Free at this size |
| **IAM roles** | `streamgt-lambda-api`, `streamgt-head`, `streamgt-exec` | Permission badges worn by running code. The Lambda's role permits exactly: read/write those S3 files, start the pipeline task, read those parameters. Nothing else |
| **CloudWatch Logs** | `/aws/lambda/streamgt-api`, `/ecs/streamgt-head` | Everything the code prints, plus crashes. The first place to look when something breaks. Kept 30 days |
| **VPC, subnets, security group** | `sg-0a952b15762b85860` | The private network the pipeline task runs inside. The Lambda doesn't use it — it talks to Neon and S3 over the public internet, with TLS |

A note on IAM, because it is the part people find strangest: permissions are not attached to
people but to *running things*. The Lambda has a role; the pipeline task has a role. If the code
tries something its role doesn't allow, AWS refuses. This is why a bug can't quietly delete your
FASTQs — the API's role has no permission to.

## What costs money

| Kind | Examples here | Behaviour |
|---|---|---|
| **Per use** | Lambda requests, Fargate seconds | Zero when idle. A pipeline run is ~$0.50/hour |
| **Per month, for storage** | S3 files (~6.5 GB), ECR images | Small and constant: cents |
| **Per hour, regardless of use** | *(none any more)* | This is what a load balancer, an always-on server, or a never-sleeping database cost. Removed in Sept 2026 |

Plus 22% VAT on everything.

The thing to watch: **anything billed per hour**. If you ever add a load balancer, a NAT gateway,
an EC2 instance or an RDS database, you have re-introduced a fixed monthly cost. Those four are
the usual culprits behind a surprising bill.

Data *into* AWS is free; data *out* to the internet is ~$0.09/GB after the first 100 GB each
month. Work done inside the region — the pipeline task reading FASTQs from S3 — is free to move.

## Where to look when you need something

| Question | Where |
|---|---|
| What am I being charged for? | Billing → **Cost Explorer**, group by Service. The console is free; the API costs $0.01 per query |
| Is the API misbehaving? | CloudWatch → Log groups → `/aws/lambda/streamgt-api` |
| Did a job run, and what happened? | ECS → Clusters → `streamgt` → Tasks; then `/ecs/streamgt-head` logs |
| Where are the files? | S3 → `streamgt-data-236726878099` |
| What is the app's address? | https://d2qy3qqpz2ebmu.cloudfront.net |

Handy commands:

```bash
# last 10 minutes of API logs, following live
aws logs tail /aws/lambda/streamgt-api --since 10m --follow

# pipeline tasks, running or recently stopped
aws ecs list-tasks --cluster streamgt --desired-status RUNNING
aws ecs list-tasks --cluster streamgt --desired-status STOPPED

# this month's cost by service (each call costs $0.01)
aws ce get-cost-and-usage --time-period Start=2026-09-01,End=2026-10-01 \
  --granularity MONTHLY --metrics UnblendedCost --group-by Type=DIMENSION,Key=SERVICE
```

## Vocabulary you'll meet

| Word | Means |
|---|---|
| **Region** | The city the hardware is in (`eu-central-1` = Frankfurt) |
| **Availability zone** | One data centre within a region; there are three here for resilience |
| **Bucket / object / prefix** | An S3 container / a file / a folder-like path such as `results/` |
| **Container image** | Software plus dependencies frozen into one runnable package |
| **Task definition / task** | The recipe for a container / one running copy of it |
| **Fargate** | "Run this container, AWS supplies the machine" |
| **Role / policy** | A badge worn by running code / the list of what it may do |
| **Cold start** | The extra second or two when idle code has to start up first |
| **Serverless** | Servers still exist; you just don't rent, patch or size them. Billing follows use |
